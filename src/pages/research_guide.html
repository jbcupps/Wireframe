GETTING STARTED

What this workspace does

The workspace records three ordered pieces, A, B and C. Each piece is a word: a sequence of twist and loop labels. Browse generated words, import the workbook, or load a prepared batch. A separate, explicitly supplied geometry allows the Python assessor to run its available checks.

  1. Choose or assemble a candidate.
  2. Supply its geometry when you have a defined model.
  3. Run an assessment or batch and read each check's evidence.
  4. Export a JSON checkpoint to retain the inputs and reports.

Without supplied geometry, candidates remain not tested. The labels alone do not define shapes, joining maps or physical particles. This workflow does not yet establish whether a candidate is smooth or dynamically stable.

CATALOG

Words and ordered triples

Individual words lists sequences for one piece. Choose A, B or C beside a row to place it in the builder. Ordered triples lists complete A/B/C candidates; Use triple loads all three pieces.

The vocabulary has 32 labels: 12 twists, 8 axis loops and 12 plane loops. Order and repetitions are preserved. Opposite signs do not cancel automatically. The empty word is a valid sequence with no operations.

A maximum of three operations per piece gives 33,825 words and 38,700,218,390,625 ordered triples. These count formal descriptions. The workbook's 216 supplied triple examples are a separate, small selection.

Find word accepts an exact sequence, a stable P ID, or a word rank. Page size changes the displayed rows, not the total catalog. Export this CSV page saves only the displayed rows. See indexing and candidate identity.

Indexing scope and starting ranks

A rank is a position in a particular ordering. Rank 0 is the first entry. Maximum operations sets the largest word length allowed for each piece in a bounded slice; it does not require every piece to have that length.

ScopeMeaning
Bounded sliceWords from length zero through the chosen maximum. Triple ordering changes C first, then B, then A, like three nested counters.
Unbounded indexNo theoretical length bound. Nested Cantor pairing assigns one rank to the three word ranks. A finite page or batch still has resource limits.
Imported catalogA zero-based position within the imported rows, separate from the source row and generated rank.
Prepared listA position in an explicitly supplied candidate list, preserving workbook example order.

The same generated triple rank can select different candidates when the scope or maximum changes. Keep those settings with the rank. A batch's full range must fit the chosen slice. Use catalog bounds copies generated catalog settings; it is unavailable for an imported catalog.

Stable IDs and source references

A piece ID begins with P and encodes its exact ordered sequence. P00000 is the empty word. A triple ID has the form TR-P00001-P00013-P00021, in A/B/C order. Swapping pieces generally changes the triple ID.

A generated rank, CSV source row, Excel row and workbook label such as C0001 are separate references. They are not interchangeable with the stable candidate ID. Imports check supplied identities against their operation sequences.

Import explorer CSV

Use Catalog → Import explorer CSV for the full 33,825-configuration file or a larger compatible catalog. Files must use UTF-8 and the explorer headers. Export a catalog page to inspect the supported format.

The browser validates the file in the background and keeps it on your device. Progress shows bytes read and rows validated. Cancel import keeps the previous catalog. After validation, browse up to 20 rows per page, or fewer for long words. Return to generated catalog restores generated browsing.

Limits are 250,000,000 bytes, 2,000,000 data rows and 30,000,000 operations in total, plus 64 columns, 64,000,000 cells and 1,000,000 bytes per CSV record.

Keep the original file: the imported catalog lasts in this tab until replacement or reload. CSV import does not automatically save or assess rows. Spreadsheet status text supplies no geometry or assessment evidence.

Upload the existing workbook

Choose Excel workbook accepts the supported 4D-NOD .xlsx layout, up to 3,000,000 bytes. It is sent to the server for bounded parsing during that request and is not saved as a server-side library. Older .xls and macro-enabled workbooks are unsupported.

Select a worksheet. First data row (1-based) chooses a position among that sheet's data rows; the table separately shows original Excel row numbers.

  • Configurations: choose a sequence for A, B or C.
  • Triple examples: use one triple or add the displayed page of up to 20 triples to the notebook.
  • Scope and schema / Operation inventory: read the workbook's reference material.

Show this page in catalog copies only the displayed candidate page. Saved triples retain the filename, workbook hash, sheet, Excel row and source ID. They initially have no geometry or results. Export saved candidates before leaving; reopening the workbook requires selecting the file again.

Generate and run a batch

  1. Choose a scope, maximum operations where applicable, starting rank, and number of triples.
  2. Choose the geometry source.
  3. Use Prepare batch to inspect the candidates, or Generate & run to create and start the batch.
  4. Keep the page open. Pause stops the queue; Run / resume selected batch continues pending records.
  5. Export the checkpoint and results.

A batch has 1–100 records and shares the notebook's total capacity. It runs one request at a time and checkpoints each returned result. Closing the page stops the browser queue; this is not a scheduled background job.

Errors stop the run while keeping completed evidence. A request exceeding 45 seconds is interrupted and left pending for retry. Browser interruption does not guarantee immediate cancellation of server work. For an existing workbook batch, use the prepared-batch workflow.

Run the 216 supplied workbook examples

The prepared notebook files contain explicit ordered lists of 100, 100 and 16 examples. They preserve the workbook's original order and source references, rather than consecutive generated triple ranks.

  1. Export existing notebook work you want to retain. The first two files each need all 100 notebook slots free.
  2. Choose Import prepared notebook and select one prepared JSON file.
  3. Select its named batch under Prepared batches, then click Run / resume selected batch.
  4. Save its checkpoint JSON and results CSV.
  5. Use Remove selected batch after saving exports, then import the next file.

Generate & run creates a new generated range; it does not run the imported list. Removal asks for confirmation and removes only the selected batch. Unrelated notebook records remain.

The workbook examples have no supplied geometry. Their prepared files start with null geometry and pending results. Running them reports not tested / symbolic, not evidence of smoothness or stability.

Choose a geometry source

Match saved notebook geometry by candidate ID uses geometry already saved for the exact ordered A/B/C identity. Save that candidate with its intended geometry first. If saved records assign conflicting geometries to it, preparation stops so you can resolve the conflict.

Symbolic only · no geometry prepares descriptions with null geometry. Unmatched candidates also remain without geometry. The currently loaded control is never automatically assigned to other words. Prepared notebook imports retain their explicitly supplied inputs.

The application does not derive a model from twist or loop labels. See the geometry format.

Checkpoints and exports

Checkpoint JSON retains full candidate inputs, geometry, source references, batch information and reports with model versions and evidence. Use it to preserve and later import work. The automatic-download option saves a checkpoint when a batch completes.

Results CSV provides a comparison table with assessment state, geometry source and source references. It is not a complete replacement for JSON. Catalog CSV export is a separate action and contains only the displayed catalog page.

Imported reports are archived until rerun and do not immediately become active evidence. Valid results restored from this browser's saved state can be reused when their saved inputs match. Export before removing records, clearing browser data, or reloading after a storage warning.

The session notebook

Save to notebook retains the current candidate and supplied geometry. The notebook holds up to 100 records and 9,000,000 serialized bytes, subject to browser storage availability. A 100-record prepared batch therefore needs an empty notebook.

Assess pending records processes saved records while the page remains open. The queue can be paused and resumed. Results stay attached to their original inputs.

Storage is local to this browser and device. There is no research account database or automatic cloud backup. Export notebook JSON for durable retention and transfer. Import files are capped at 10,000,000 bytes and must still fit the notebook's record and byte budgets.

Assemble A, B and C

Each piece has its own ordered sequence. Add an operation, move it up or down, repeat it, remove it, or apply an edited sequence. The empty word is permitted. Repetitions remain explicit, and opposite signs are not simplified.

For example, Txy+ · Lw− has two operations. These are provisional symbolic labels; w does not by itself define physical time. Editing a sequence changes its candidate identity and invalidates the displayed assessment.

Piece colors distinguish A, B and C; they do not represent QCD color charge. Supply and inspect the intended geometry separately before saving or assessing the candidate.

Supply an explicit geometric model

The assessor accepts a versioned finite simplicial complex. A simplex lists its vertices; five vertices form a 4-simplex. Each of A, B and C supplies its maximal simplices. Shared vertex labels identify shared faces across pieces.

Use Import geometry JSON or edit and apply the JSON directly. Load a control to inspect a complete valid example, then export it if you need a template. Inputs are declarative data; Python code in them is not executed.

Declare joining.target as closed, exterior_interface, or unspecified. An intended exterior interface needs its exact expected_exterior_faces list. A boundary is checked against that target, rather than always being treated as an error.

Model fields record the underlying space, operation definitions, composition, equivalence rules, differentiability, metric, time convention and physical mapping. A declaration's presence does not mean the assessor implements or verifies it. This format cannot express every triangulation, self-identification, smooth atlas or physical geometry.

Without coordinates, the view is an incidence schematic. With coordinates, it projects the supplied positions. Animation requires supplied frames and is labeled with their declared meaning. Neither projection nor animation proves geometric or physical validity.

Use controls to understand the checks

Controls are known mathematical inputs for checking the assessor. Loading one supplies geometry for the current workspace candidate; it does not establish that the symbolic labels imply that geometry.

ControlWhat it illustrates
Three-piece 4-sphereThe boundary of a 5-simplex, partitioned into three pieces. No boundary tetrahedra; mod-2 Betti numbers [1, 0, 0, 0, 1].
Branched tetrahedronThree 4-simplices share one tetrahedron. Its incidence of three is an obstruction detected by the facet check.
Singular vertexTwo 4-sphere boundaries meet at one vertex. Facet incidence passes, but the vertex link is disconnected.

These are not particle models. The singular-vertex control demonstrates why passing one check cannot establish a manifold.

Run and interrupt an assessment

Run Python assessment submits the current candidate and supplied geometry for one bounded calculation. With geometry, reports include dimensions, purity, connectivity, simplex and boundary counts, Euler characteristic, exact mod-2 Betti numbers and applicable obstruction checks.

Without geometry, the symbolic candidate is recorded and geometric and physical checks remain not tested. A resource-limit response asks you to reduce the input before retrying.

Interrupt request stops the browser from waiting for the response. Server work remains subject to its calculation budget. Export a returned report to retain its inputs, assumptions, assessment time and test version.

Interpret the evidence

StatusInterpretation
PassedThe specified check passed for this input under its stated assumptions. Read its evidence and limitations.
FailedThe check found a mismatch or obstruction in its applicable setting. Inspect its witness or explanation.
Not testedThe required input or implemented test is absent. This is not a pass.
UndeterminedThe available evidence does not resolve the property. It remains an open question, rather than an established pass or failure.
CompletedThe available computation finished. This overall report state does not establish a valid manifold or particle.

Facet incidence counts how many top-dimensional simplices meet at a face. A disconnected vertex link gives an obstruction, but a connected link does not prove the required sphere or ball neighborhood. Exact mod-2 homology describes algebraic invariants; it does not classify manifolds or prove orientability.

The workflow does not establish full manifold structure, smoothness, orientability, Pin structure, causality, dynamical stability or particle identity. A report can pass its available checks while an untested singularity remains. Physical benchmark values are comparison inputs, not derived predictions.

Which limit applies?

Catalog imports, workbook uploads, notebooks and assessments have separate bounds. Importing a large catalog does not increase the size of an individual assessment or notebook.

Explorer CSV250 MB; 2,000,000 rows; 30,000,000 operationsSplit the source file, keeping explorer headers in each part.
Excel workbook3 MB; supported .xlsx layoutUse a smaller workbook or explorer CSV for a large candidate catalog.
Displayed catalog pageUp to 20 rows in the UI; 20,000 operations across the pageReduce rows per page, down to one for long words.
Candidate piece4,096 operationsUse a shorter explicit input.
Batch preparation1–100 records; 20,000 displayed operations; must fit notebook capacityUse smaller batches. Export and remove completed work before the next import.
Notebook100 records; 9 MB serialized records; imports at most 10 MBExport and remove records. Browser storage may impose a smaller practical limit.
Assessment request512 KiB; 150 maximal simplices; 250 vertices; at most 5 vertices per simplexSimplify the complex and keep separate inputs in separate requests.
Assessment calculationCooperative 8-second budgetReduce the complex after a resource-limit response.

MB means 1,000,000 bytes; KiB means 1,024 bytes. Other format and validation bounds are reported when applicable. These are computational bounds, not theoretical limits on repetition or the mathematical search space.
